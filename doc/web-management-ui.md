# Web Management UI — Technical Documentation

## Overview

A lightweight single-page web application for the Unfolded Circle Dock 3 (UCD3),
running on an ESP32-S3 with ESP-IDF SDK 5.4. The UI provides device configuration,
IR control, serial communication, and firmware updates via a WebSocket JSON API.

## Design Decisions

### Single-Page Application

All pages are sections within a single `index.html`, toggled via CSS class `.hidden`.
No client-side router, no hash-based routing. Reasons:

- Minimizes HTTP requests (one HTML load)
- Avoids multiple file entries in FrogFS
- Keeps navigation logic trivial (~20 lines)

### No ES Modules

The codebase uses ES5-compatible patterns (`var`, function expressions, object literals)
intentionally. All target browsers support ES6+, but the code avoids features that
complicate minification or require transpilation. No module bundler is used.

### Script Loading Order

```html

<script defer src="lang.js"></script>
<script defer src="app.js"></script>
```

`defer` guarantees execution in document order after DOM parsing. `lang.js` defines
`LANG_DATA` which must exist before `app.js` calls `I18N.init()`.

### Dark Theme

Dark background (rgb(20,20,20)) with light text. Matches the product’s design language.
No theme switching — the device UI is always dark.

### Navigation: Horizontal Tabs

```
[Status] [General] [Network] [IR] [Ports] [OTA]
```

- Desktop: horizontal tab bar
- Mobile (<600px): horizontally scrollable (overflow-x: auto, hidden scrollbar)
- Scales to 6+ tabs without layout changes

Chosen over hamburger menu (too hidden) and vertical sidebar (overkill for 6 pages).

## WebSocket Communication

### Connection Flow

```
    Browser                            Dock
      |--- WebSocket connect ---------->|
      |<-- {"type":"auth_required"} ----|
      |                                 |
      |    [token in sessionStorage?]   |
      |    YES: send auth               |
      |    NO:  show login dialog       |
      |                                 |
      |--- {"type":"auth","token":"X"} >|
      |<-- {"type":"authentication",    |
      |      "code":200}                |
      |                                 |
      |    [authenticated, load page]   |
```

### Message Format

Request (client to dock):

```json
{
  "type": "dock",
  "id": 1,
  "command": "get_sysinfo"
}
```

- `id` is monotonically incremented per request
- `id` is reflected as `req_id` in the response for correlation

Response (dock to client):

```json
{
  "type": "dock",
  "req_id": 1,
  "msg": "get_sysinfo",
  "code": 200,
  "name": "My Dock"
}
```

Event (dock to client, unsolicited):

```json
{
  "type": "event",
  "msg": "ir_receive",
  "ir_code": "17;0x2A4C0A84820C;48;0"
}
````

### Reconnection Strategy

- Exponential backoff: 2s, 3s, 4.5s, … max 30s
- On reconnect: auto-authenticate with stored token
- On auth failure after reconnect: show login dialog
- All pending promises are rejected on disconnect

### Token Storage

- `sessionStorage`: survives page reload, cleared on browser/tab close
- Never stored in `localStorage` (security consideration)
- On successful token change: update stored token for reconnect

## Authentication

- Token stored in `sessionStorage` (key: `"token"`)
- Login dialog appears when accessing protected tabs without auth
- ESC closes login dialog, returns to current page
- After successful auth, navigates to the tab that triggered login (`pendingPage`)
- Logout: clears token, closes WebSocket, navigates to Status

### OTA Upload Authentication

OTA uses HTTP POST with Basic Auth:

    Authorization: Basic base64("admin:" + token)

The WebSocket token doubles as the HTTP password.

## Internationalization (i18n)

### Architecture

```
    Source (Git/Crowdin)         Build                    FrogFS
    ─────────────────────       ──────────────          ────────────────
    lang/en.json        ─┐
    lang/de.json         │     build_lang.py            lang.js.gz
    lang/fr.json         ├───> merge + wrap  ─────────>  (single file,
    lang/it.json         │     as JS object              gzip only,
    lang/es.json         │                               NO uglify-js)
    lang/pt.json         │
    lang/nl.json        ─┘
```

### Why a Single Merged File

- gzip efficiency: identical keys repeat across languages, deflate back-references
  make additional languages nearly free (~500 bytes per language after gzip)
- No extra HTTP requests: loaded synchronously via `<script defer>`
- Atomic deployment: languages always match the firmware version

### Why Separate Source Files

- Crowdin compatibility: flat JSON format, one file per language
- Contributor DX: easy to find, edit, and submit a single language file
- Git diffs: changes to one language don't pollute other files

### FrogFS Constraint

FrogFS has a fixed set of known transforms (`uglify-js`, `uglifycss`, `html-minifier`,
`gzip`, `discard`). It does NOT support arbitrary commands like `terser`.

CRITICAL: `uglify-js` produces 0-byte output for `lang.js` (likely due to file size
or content structure). Therefore `lang.js` must be filtered separately without `uglify-js`.
See frogfs.yaml section below.

### Build Script: scripts/build_lang.py

- Reads all `webroot/lang/*.json` files
- English (`en.json`) is the full reference (all keys + values)
- Other languages: only keys that differ from English are included (reduces size)
- Output: `var LANG_DATA={...};\n` with `ensure_ascii=True` (ASCII-safe for all tools)
- Strings identical to English are not duplicated (e.g., "SSID", "RS232", "UART")

### Runtime Engine

```javascript
I18N.init()           // Detect language, resolve strings, apply to DOM
I18N.t("key")        // Lookup for dynamic strings (toasts, confirms)
I18N.t("key", {x: 1}) // With template variables: "Port {x}" -> "Port 1"
I18N.setLang("de")   // Switch language, re-render DOM
```

### DOM Binding

```html

<button data-i18n="btn_save">Save</button>
<input data-i18n-ph="ph_token" placeholder="Token">
<span data-i18n-title="tip_info" title="Info">
```

English text remains in HTML as fallback if `lang.js` fails to load.

### Language Detection Priority

1. `localStorage.getItem("lang")` — user’s manual choice (persistent)
2. `navigator.language` — browser/OS language (base code, e.g., “de” from “de-CH”)
3. Fallback: `"en"`

### Adding a New Language

1. Copy `webroot/lang/en.json` to `webroot/lang/xx.json`
2. Translate values (keys remain English)
3. Build — `build_lang.py` picks up new file automatically
4. Language appears in footer selector without code changes

### Crowdin Configuration

```yaml
# crowdin.yml
files:
  - source: /webroot/lang/en.json
    translation: /webroot/lang/%two_letters_code%.json
    type: json
```

## CSS Architecture

- Single file, no preprocessor, no CSS variables
- Mobile-first responsive breakpoint at 600px
- Card-based layout (`.card` class)
- Status lists reuse `<ul><li>` pattern from original firmware status page
- `accent-color` for range inputs and checkboxes (modern browsers only)
- Console areas: fixed height of 8 lines (`calc(8 * 1.4em + 16px)`)
- Dark theme only, no theme switching

## JavaScript Architecture

### Module Structure (single file, namespace pattern)

    app.js
    ├── I18N          — Internationalization engine
    ├── WS            — WebSocket communication layer
    ├── Toast         — Notification system
    ├── UI            — Page controller, navigation, login
    └── Pages         — Page-specific logic
        ├── Status
        ├── General
        ├── Network
        ├── IR
        ├── Ports
        └── OTA

### Error Handling

- API errors surface as Toast notifications (global, bottom-center)
- Toast types: success (green, 3s) and error (red, 5s)
- `Toast.error(msg)` formats code + message from API response
- Network errors (disconnect, timeout) reject pending promises

### Serial Console

- Explicit enable/disable via `enable_serial_events` command
- Events received via `WS.on("serial_data", handler)`
- Output buffer limited to 4 KB (oldest data trimmed)
- Send appends terminator character when buffering mode is "line"
- Terminator displayed/configured as hex value (e.g., `0x0D`)

### IR

- Send: textarea for code, format dropdown (hex/pronto), output checkboxes
- Output checkboxes disabled based on actual port mode (`get_port_modes`)
- Learn: toggle button, events via `ir_receive`, displayed in console area
- `int_top` field always sent as `false` (deprecated, not removed from API)

## Build Integration

### CMake (root CMakeLists.txt)

```cmake
find_package(Python3 REQUIRED COMPONENTS Interpreter)
add_custom_target(generate_lang ALL
    COMMAND ${Python3_EXECUTABLE} ${CMAKE_SOURCE_DIR}/scripts/build_lang.py
    COMMENT "Generating lang.js from language files"
    WORKING_DIRECTORY ${CMAKE_SOURCE_DIR}
)

target_add_frogfs(${PROJECT_NAME}.elf)
add_dependencies(${PROJECT_NAME}.elf generate_lang)
```

### FrogFS Configuration (frogfs.yaml)

```yaml
collect:
  - $cwd/webroot

filter:
  "**/.DS_Store":
    - discard
  "**/*.bak":
    - discard
  "**/lang":
    - discard

  "webroot/app.js":
    - uglify-js
    - gzip -9 -f -c

  "webroot/lang.js":
    - gzip -9 -f -c

  "**/*.css":
    - uglifycss
    - gzip -9 -f -c

  "**/*.html":
    - html-minifier
    - gzip -9 -f -c

  "**/*.ico":
    - gzip -9 -f -c
  "**/*.svg":
    - gzip -9 -f -c
```

Key points:

- `**/lang` discards source JSON files (only `lang.js` ships)
- `lang.js` explicitly skips `uglify-js` (produces 0-byte output for this file)
- All text assets are gzip-compressed at build time
- HTTP handler serves with `Content-Encoding: gzip` when client supports it

## HTTP Caching Strategy

- `ETag` header: firmware version string (changes on every build)
- `Cache-Control: no-cache` — browser caches but revalidates every request
- 304 Not Modified returned when `If-None-Match` matches current version
- After firmware update: new ETag forces fresh download

## Development Mode

Serve files locally without flashing the Dock to test the web-app, while using a WebSocket connection to a real Dock.

Using Python (built-in, no installation needed):

```shell
cd webroot
python3 -m http.server 9000
```

Or with Node.js:

```shell
cd webroot
npx serve -l 9000
```

Now you can test with:

```
http://localhost:9000/?dock=$IP_OF_DOCK3
```

- use `dock` parameter to specify the Dock IP address you want to connect to.

⚠️ Remember to create the unified `webroot/lang.js` file from the language files with the [tools/build_lang.py](../tools/build_lang.py)
script! You can also run the IDF firmware build command.
